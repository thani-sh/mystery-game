# Mystery Game — Content-Driven Scaling Refactor Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Refactor the PixiJS mystery-game PoC so adding levels, actors, dialogue, and scenes means adding **data (JSON) + assets** and (almost) no code.

**Architecture:** Enforce the 3-layer design already promised in ADR-002 (engine / app / game) with (1) a `SceneManager` that swaps typed scenes by id, (2) a `ContentIndex` registry that loads all JSON content folders at build time with cross-reference validation, (3) a pure `GameState` service (flags + current level/player) that survives level transitions, and (4) an extended, strictly-typed content schema where a level file declares its player, actors, dialogues, triggers, and exits — everything else derives from it (asset loading included).

**Tech Stack:** PixiJS v8, TypeScript (strict), Vite, ESLint/Prettier, vitest (new, for pure game-layer logic). No new runtime deps. Content validated by a dependency-free Node script at build/lint time.

## 2. Target Content Model

All content lives in `game/src/game/data/` (build-time bundled JSON via `import.meta.glob`, typed with `satisfies`):

```
game/src/game/data/
├── game.json                  # boot config: title, startScene/startLevel, default player actorId
├── characters/<actorId>.json  # ActorConfig (display, sprite root, scale, portrait)
├── levels/<levelId>.json      # LevelConfig (below)
└── types.ts                   # all content types (or split per-domain later)
```

**ActorConfig** (replaces `CharacterData`):
```ts
export interface ActorConfig {
  id: string;                 // folder name under public/assets/actors
  displayName: string;        // shown in dialogue
  scale?: number;             // vs TILE_SIZE (64); default 1
  // derived paths (convention, not stored):
  // frames: /assets/actors/<id>/frames/{idle|walk}.json  (animations: down|up|left|right)
  // portrait: /assets/actors/<id>/speech/talking.png (optional)
}
```

**LevelConfig** (extends current `LevelData`, schema v2):
```ts
export interface LevelConfig {
  id: string;
  title?: string;
  background: string;         // /assets/levels/<id>.webp
  imageResolution: { width: number; height: number };
  scalingFactor?: number;
  player: { actorId: string; start: Position };   // was: implicit "bets" + playerStart
  actors: LevelActor[];       // was: characters[]
  dialogues?: Record<string, DialogueNode>;       // kept per-level (see §6 note)
  scripts?: Record<string, Action[]>;
  triggers?: Trigger[];       // NEW: region + once + scriptId
  exits?: LevelExit[];        // NEW: walk-out-of-level transitions
  collisions?: Rectangle[];
}
export interface LevelActor {
  id: string;                 // instance id (references ActorConfig.id by default)
  actorId: string;            // NEW — which ActorConfig/sprite to use
  position: Position;
  facing?: "down" | "up" | "left" | "right";
  interactable?: boolean;
  dialogueStart?: string;     // key into dialogues
  scriptIdOnTalk?: string;    // optional one-shot script instead of dialogue
}
export interface LevelExit {
  id: string;
  zone: Rectangle;            // player overlaps => transition
  targetLevel: string;        // LevelConfig.id
  spawn: Position;            // position in target level
}
export interface Trigger {
  id: string;
  zone: Rectangle;
  once?: boolean;             // default true
  scriptId: string;           // key into scripts
}
```

**Actions** (discriminated union; extend by adding a case + executor):
```ts
export type Action =
  | { type: "move_actor"; actorId: string; target: Position; durationMs?: number }
  | { type: "set_flag"; flag: string }
  | { type: "clear_flag"; flag: string }
  | { type: "load_level"; levelId: string; spawn?: Position }
  | { type: "message"; speakerActorId?: string; text: string };  // optional, portable dialogue
```

**DialogueChoice** gains conditions + unified effects:
```ts
export interface DialogueChoice {
  text: string;
  next?: string;             // node key
  scriptId?: string;         // run script (may set flags / move / load_level)
  requiresFlag?: string;     // hide choice unless flag set
  blocksFlag?: string;       // hide choice if flag set (choice already taken)
}
```

## 6. Design Notes / Decisions

- **Dialogues stay per-level** in v1 (as today) — global shared dialogue hubs can move to `dialogues/*.json` later without schema break (a `dialogueRef` field). YAGNI now.
- **Player as data**: `game.json.defaultPlayerActorId` + per-level override — future "play as another character" costs nothing.
- **Cross-ref validation at build time, not runtime** — catches broken content before it ships; runtime code then trusts the registry.
- **Two "data" dirs clarified**: `src/game/data/**/*.json` = game content (typed, bundled); `public/assets/**` = processed binaries + generated sheet manifests (AssetPack/tool output). `public/assets/levels/level1.json` manifest and the bg path coexist; validator asserts the path the level references actually exists.
- **Movement/grid stays as-is** (free movement + AABB collisions) — tile-grid migration is out of scope.
- **Prettier enforced from Phase 0 on** (`npm run build` runs lint) so refactor commits stay green.

## 8. Risks, Tradeoffs, Open Questions

- **Scope creep into ADR-003 systems** (clues, journal, A*): explicitly out; the refactor only guarantees *content* extensibility, not new gameplay.
- **Asset art bottleneck**: level2 background is art, not code — may need placeholder art or art tooling run; plan task 7.1 anticipates it.

- **Vite base path / Pages subpath** may already be broken (finding 6) — confirm early (0.2), fix is 1 line.
- Goon `scale: 6` visual bug may surface once NPC loading is generalized — flag to designer, don't silently "fix".
